# Plan: Starling-owned ggml engine for parakeet-tdt + moss

## Goal

Bring the ggml inference implementations of parakeet-tdt and moss **into the Starling repo** as first-party, Starling-authored C++ code — replacing the current external-binary shelling (`parakeet.cpp` via `libparakeet.so`, CrispASR via subprocess). One shared ggml runtime serves both models. Driven from Python via ctypes (the proven `_ggml_parakeet_native.py` pattern). Targeting **byte-exact** on short/medium/long for parakeet (already proven) and **byte-exact for moss too** (achievable — the reference uses a bf16 KV cache, so a ggml bf16 KV matches it; the prior "f16-KV divergence" was CrispASR-specific, not fundamental).

Architecture decision (from your "most performant + most portable" answer): **C++ core + ctypes**. This is both the fastest (in-process CUDA-graph capture/replay, proven 16ms parity) and the most portable (ggml compiles to CUDA/Metal/Vulkan/HIP/SYCL/CPU from one codebase). It's why parakeet.cpp and CrispASR were written in C++ in the first place.

This is NOT a copy/fork of parakeet.cpp. Starling authors clean first-party C++ that **mirrors parakeet.cpp's proven architecture** (Backend / ReplayGraph / ModelLoader — there is effectively one good way to wrap ggml for this workload) but is Starling-owned, serves both models from one runtime, and lives in Starling's tree in Starling's style.

## Scope and phasing

Large effort (~10–12k LOC C++ across both models + shared runtime). You asked to go **all the way through moss** before review, so the plan is one continuous implementation with internal checkpoints (each gated on byte-exactness before proceeding). If a checkpoint fails badly, I stop and report rather than push through.

- **Phase 0 — Foundation** (shared runtime + build + ctypes + engine wiring, ~1.5k LOC)
- **Phase 1 — Parakeet** (encoder + mel + TDT decode, ~6.5k LOC) — the proven model, validates the whole architecture
- **Phase 2 — Moss** (audio encoder + Whisper mel + Qwen3 LLM decode with bf16 KV, ~5–6k LOC) + add moss component goldens
- **Phase 3 — Perf + docs** (port the byte-exact perf wins; update docs)

## Build integration (the "optional C++" requirement)

- **hatchling is NOT touched.** The wheel stays pure-Python. (Per exploration: a hatch build hook coupling CMake into every `pip install` fights the optionality requirement; the project has no such hook today and the precedent — `_kernels/cuda_backend.py` JIT + `_ggml_parakeet_native.py` — is "discover a built artifact at runtime".)
- Build the C++ with a documented `cmake -B build -DSTARLING_GGML_CUDA=ON && cmake --build build` step, mirroring parakeet.cpp's `CMakeLists.txt` structure: `add_subdirectory(third_party/ggml)` + `FORCE`-set `GGML_*` backend options + `apply_ggml_patches.sh` at configure time + `STARLING_GGML_SHARED=ON` produces `libstarling_ggml.so`/`.dylib`/`.dll` with `WINDOWS_EXPORT_ALL_SYMBOLS ON` (for ctypes on Windows).
- The `.so` is discovered by `src/starling/_ggml/_native.py` via a search order: env var `STARLING_GGML_LIB` → package-relative → `build/libstarling_ggml.so`. Gracefully returns `available()=False` if absent (the `_ggml_parakeet_native.py` pattern).
- New `docs/ggml-engine.md` build section rewritten to point at the in-tree build (replacing the external-repo instructions).
- Cross-platform: carry the Windows landmines from parakeet.cpp's `release.yml` (explicit Git-Bash patch application, `_USE_MATH_DEFINES`, `GGML_CUDA_NO_VMM` on headless, `GGML_METAL_EMBED_LIBRARY` on macOS, `GGML_NATIVE=OFF` for distributable builds).

## The shared runtime (Phase 0)

Mirror parakeet.cpp's proven infra (file:line refs in the exploration; I'm reusing the *architecture*, not copying files):
- `Backend`: registry-driven device selection (CUDA/Metal/Vulkan/HIP/SYCL/CPU via `PARAKEET_DEVICE`-equivalent env var), persistent `gallocr` reused across calls (never `backend_sched` on the fast path — it re-plans per call), zero-copy weights via `clone_weight` returning loader tensors directly.
- `ReplayGraph`: build-once/replay-many, **stable cgraph uid** (skips ggml-cuda's per-replay O(n_nodes) memcmp), **private gallocr per graph** (so coexisting graphs' device pointers don't invalidate), **async `set_input` + async readback + single sync** (the per-replay host-overhead fix).
- `ModelLoader`: GGUF parse + KV helpers + weight realize (CPU zero-copy buffer borrow; GPU mirror + upload). Only the `parakeet.*` / `moss_transcribe.*` key strings are model-specific — the mechanism is generic, shared.
- Shutdown ordering: `clear_decode_caches → backend.reset → flag`, registered via `std::atexit` BEFORE the CUDA driver's handler (the teardown-crash fix, already proven in parakeet.cpp 7c2323e — this time built in from the start).
- C API shell: flat `extern "C"`, ABI version, opaque context `{unique_ptr<Model>}`, exception fencing, `last_error`, `shutdown`.

## Parakeet (Phase 1) — the proven model

Reimplement the parakeet-tdt model. The math is fully specified in `src/starling/parakeet/ALGORITHM.md` + `docs/ggml-fused-ops-spec.md`. Build each component as a graph builder appending ops to a shared `ggml_context`, referencing zero-copy weight leaves by verbatim NeMo tensor name.

- **Mel**: CPU FFT (double-precision preemph/framing/windowing — kept on host because moving to GPU float breaks byte-exactness) + GPU DFT-as-matmul path with a per-`T` `ReplayGraph` cache (the 7c2323e win).
- **Encoder**: 24-layer macaron Conformer. Subsampling (dw_striding ÷8) → xscaling → pos_enc → 24× (FFN1 → relpos attention via `ggml_flash_attn_ext` with per-head mask → conv module via `ggml_conv_2d_dw_direct` → FFN2 → norm_out). Per-shape `EncReplay` cache. Conv pointwise weights loaded f16 (the 7400510 win). NORM+MUL+ADD via the fused kernel (carried patch 0005).
- **Decode**: TDT greedy serial loop (the correctness reference) + K-step multistep (K=16 short/medium, K=64 long — the proven byte-exact values) capturing K decode steps in one graph with on-device argmax/frame-advance/blank-skip, one sync per K steps.
- **Byte-exact gate at each stage** using the existing component goldens: `golden/parakeet_tdt_{mel,_mel_mask,_enc,_ids}.pt` let me validate mel → encoder → decode independently, then `golden/parakeet_tdt_{short,medium,long}_text.txt` end-to-end. The `test_ggml_parity.py` gate (exact string match) must pass.

## Moss (Phase 2) — the new ground

**First add moss component goldens** (none exist today — only end-to-end ids/text). Extend `scripts/moss_golden.py` to also dump `moss_{short,medium,long}_{mel,_audio_embeds,_inputs_embeds,_prefill_logits}.pt` so I can validate mel → encoder+adapter → embed-merge → LLM-prefill → decode stage by stage (mirroring parakeet's staged goldens). Capture from the byte-exact `reference.py` path.

Then reimplement moss. Key facts from exploration:
- **Mel**: stock Whisper log-mel (`WhisperFeatureExtractor`: n_fft=640, hop=160, dim=128, center=True, pad_mode="reflect", Hann). **Watch out**: the GGUF bakes `audio.mel_filters [128,201]` + `audio.mel_window [400]` — the 201/400 implies n_fft=400, which may differ from the Python path's 640. Resolve this against the golden mel before building.
- **Audio encoder**: 32-layer Qwen3-Omni transformer. Conv2d subsampling stack (3× stride-2 Conv2d, 8× total time downsample, GELU) → sinusoidal pos-emb (regenerate deterministically, max_pos=1500) → 32× (LayerNorm → windowed attention via `cu_seqlens` [non-causal, 100-frame chunks, 8-chunk attention window] → LayerNorm → fc1 → GELU → fc2). **LayerNorm+biases, NOT RMSNorm; GELU, NOT SwiGLU.** Then `ln_post → proj1(1280→1280) → GELU → proj2(1280→2048)`.
- **Adapter**: `MossGatedMLP` (gate/up/down, SiLU, no biases, 2048→8192→2048).
- **LLM decode**: Qwen3, 28 layers, GQA 16Q/8KV, head_dim=128, hidden 2048, SwiGLU (intermediate 6144), RMSNorm eps=1e-6, RoPE θ=1e6, per-head QK-norm (q_norm/k_norm applied before RoPE), tied embeddings (vocab 151936). Standard autoregressive greedy + K-step multistep.
- **KV cache = bf16** (the reference uses bf16 StaticCache — `reference.py:70`). This is the correct match, NOT f16. Expect byte-exact on short/medium; on long, target transcript-level agreement (cuBLAS bf16 nondeterminism makes the *reference itself* non-bit-stable on 200-token decodes — documented in `test_moss.py:300-314`).
- **Load-bearing details**: the exact Qwen3 op order (`q_proj → view → q_norm → transpose → RoPE`), the full `(1,1,T,max_cache_len)` 4D attention mask (NOT `(1,1,1,N)` which diverges by ~202), RoPE matching PyTorch ATen bf16 (not a fused approximation — `fused_decode.py:182-187` documents the fused Triton RoPE diverges).
- GGUF: `moss_transcribe` arch (custom, not `qwen3`), 840 tensors, F32 norms + F16 weights, 4.84 GB at `/home/m0hawk/asr-bench/models/moss-transcribe-preview-2b-f16.gguf`.
